# Wazuh Manager Installation (Ubuntu Server)

This document records how the central Wazuh manager and dashboard were deployed for the lab, how the network was prepared, and how the installation was validated.

## 1. Lab target

| Item | Lab value |
|:--|:--|
| Host OS | Ubuntu Server (VMware VM) |
| Hostname / cluster node | `soc` / `node01` |
| Static address | `192.168.188.132` |
| Dashboard URL | `https://192.168.188.132` |
| Agents managed | `soc-windows` (192.168.188.129), `alpine-lab` (192.168.188.130) |

> Replace the address and hostname with your own values if you reproduce the lab.

## 2. Prerequisites

- A Ubuntu Server VM with a static IP on the lab network.
- Internet access during installation (or Wazuh packages already downloaded).
- At least 4 GB RAM and 30 GB disk for the manager plus OpenSearch indexing.
- Date/time synchronized across all VMs — skewed clocks make alert timelines unreliable.

## 3. Install Wazuh

Use the official Wazuh installation assistant for the all-in-one manager + indexer + dashboard deployment. Check the official documentation for the current release before running these commands.

```bash
# Prepare the system
sudo apt update && sudo apt upgrade -y
sudo apt install -y curl apt-transport-https lsof unzip

# Download the official assistant (verify the URL against current docs)
curl -sO https://packages.wazuh.com/4.x/wazuh-install.sh
curl -sO https://packages.wazuh.com/4.x/config.yml

# Edit config.yml: set node names, IPs and dashboard credentials
nano config.yml

# Generate the installation files
bash wazuh-install.sh --generate-config-files

# Distribute the certificates to the target node(s), then install
bash wazuh-install.sh --wazuh-indexer node01
bash wazuh-install.sh --start-cluster
bash wazuh-install.sh --wazuh-server wazuh
bash wazuh-install.sh --wazuh-dashboard dashboard
```

The dashboard was accessed at `https://192.168.188.132` with the credentials generated by the assistant. Credentials are deliberately **not** stored in this repository.

## 4. Service and port verification

```bash
sudo systemctl status wazuh-manager
sudo systemctl status wazuh-dashboard
sudo ss -tlnp | grep -E '1514|1515|55000|9200|443'
```

Key ports used by the lab:

| Port | Purpose |
|:--|:--|
| 1514/TCP | Agent → manager event delivery (confirmed in the Windows agent log) |
| 1515/TCP | Agent enrollment |
| 55000/TCP | Wazuh API |
| 9200/TCP | Wazuh indexer |
| 443/TCP | Wazuh dashboard |

## 6. Index pattern and basic searches

The dashboards used the `wazuh-alerts-*` index pattern. The Discover view showed roughly **3,962 hits over 7 days**, confirming that endpoint events were actually arriving and being indexed.

Useful initial searches:

```text
agent.name: soc-windows
rule.groups: syscheck
data.win.eventdata.image: "C:\\Windows\\system32\\svchost.exe"
manager.name: soc
```

## 7. Dashboards used during the project

- **SOC Overview** — custom dashboard for failed Windows logons, Windows account changes (4720, 4722, 4724, 4732, 4738) and Linux SSH auth.
- **Discover** — raw alert inspection, including Sysmon fields.
- **File Integrity Monitoring** — FIM overview and event list.
- **Threat Hunting** — alert-level evolution, authentication success/failure, MITRE techniques.
- **MITRE ATT&CK** — techniques and tactics grouped by agent.
- **Vulnerability Detection** — CVEs, severity and affected packages.
- **System Inventory / IT Hygiene** — OS families, installed packages, running processes, destination ports.

## 8. Troubleshooting notes

- If agents show as *Disconnected*, check VM networking first, then `ss -tlnp` on the manager and the agent log on the endpoint.
- If the dashboard is unreachable, confirm the indexer cluster is healthy (`bash wazuh-install.sh --start-cluster` or `systemctl status wazuh-indexer`).
- Keep the manager time synchronized; certificate validation and alert ordering depend on correct time.
